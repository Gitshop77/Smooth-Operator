# Wave 1 — AUD-2 security+tools+llm

Read-only audit of the security layer (`security*.ts`), the tool engine (`tools/`, incl. `handlers/` and `helpers/`), and the LLM providers/protocols (`llm/providers/*`, `llm/protocols/*`). Every finding was verified against source and by direct probe (`sanitizeUntrusted` / `neutralizePromptTags` / `scanForInjection` on forged-tag payloads); the pinned suites `tests/security.test.ts` and `tests/lightpanda-result-sanitize.test.ts` (138 tests) pass and do NOT cover these cases.

- [M] src/lib/agent/security-injection.ts:38 — `PROMPT_TAGS` (the single source of truth for tag redaction) omits the three untrusted-content wrapper tags the tool handlers emit: `<untrusted_research>` (handlers/research.ts:71), `<untrusted_tab_list>` (handlers/tab-management.ts:129), `<untrusted_downloads>` (executor.ts:473). Verified: a forged `</untrusted_research>` / `</untrusted_tab_list>` / `</untrusted_downloads>` survives `sanitizeUntrusted`, `neutralizePromptTags`, and `scanForInjection` byte-for-byte (probe), so an injected research answer can prematurely close its wrapper — contained only by the outer `<untrusted_page_data>` re-wrap at the history render seam (loop/messages-utils.ts:121). Add all three to `PROMPT_TAGS` and `BARE_TAG_REDACTION_TAGS`; the G7 loop test (tests/integration.test.ts:771-805) then covers them automatically.
- [M] src/lib/agent/lightpanda/result-sanitize.ts:18 — `sanitizeResearchResult` (whose own header calls research output "the highest-trust-risk text the loop receives") never runs `sanitizeUntrusted`: it only bounds, value-redacts (`redactSecrets`), and flags (`scanForInjection`). A forged `<site_memory>…</site_memory>` block (the only explicitly TRUSTED tag) or a `%secret%` placeholder in the research answer survives at the source and is only redacted downstream at the prompt render seam (loop/messages-utils.ts:121, loop/compaction.ts:138). Run `sanitizeUntrusted` (or at least the tag/placeholder redaction patterns) on the bounded answer before returning it.
- [M] src/lib/agent/security-injection.ts:279 — the `tag-injection` detector in `scanForInjection` omits `<site_memory>` (the only tag the navigator prompt explicitly honors as trusted) and the three `<untrusted_*>` wrapper tags. Verified: a forged `<site_memory>` block yields `warnings: []`, so the LLM receives no "treat with extra skepticism" flag for the exact tag it is instructed to obey. Extend the detector alternation to cover `site_memory` and the wrapper tags (the bare-tag redaction list at line 82 is the natural source of truth).

Note: no [C] or [I] findings. The security posture checked out end-to-end: same-tab `navigate`/`search` are domain-gated content-side with SW re-checks for `new_tab` (tab-action-service.ts); `evaluate` sandbox denies `chrome`/`Function`/`eval`/`atob`/`btoa`/constructor chains with documented, contained residual risks (ownerDocument path, MV3 session-storage backstop); script steps are mode-gated via `effectAuthorizer` and nested `run_script` recursion is refused (executor.ts:231); anthropic/openai/gemini protocols correctly gate reasoning params, preserve usage accounting (incl. cached/reasoning tokens), and never log frame content; openai-compatible SSRF guards run at both `resolveProfile` and `configure`; the domain-config side-channel fail-closes whenever the enforced flag is set.
