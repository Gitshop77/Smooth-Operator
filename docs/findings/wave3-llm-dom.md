# Wave 3 — AUD-5 llm+dom

Audit of the LLM abstraction layer (`src/lib/agent/llm/` root modules, excluding `providers/` and `protocols/`) and the DOM observation layer (`src/lib/agent/dom/`, incl. `utils/`, `annotation/`, `extraction/`, `navigation/`). Read-only review; every finding verified at source.

- [C] `dom/annotation/screenshot-annotator.ts:250,283-286` — double-scaling bug: `ctx.scale(outScale, outScale)` is active while `dx/dy/dw/dh` are pre-multiplied by `scaleFactor * outScale`. Canvas transforms multiply coordinates again, so every box is drawn at `outScale×` of the correct position and size (squished toward the origin) whenever `outScale < 1`. Label padding (`sFont * outScale`, line 315) uses only one factor, confirming the second multiplication is unintentional.
- [C] Reachability proven: `background/tab-manager.ts:121-127` feeds a full-resolution CDP capture (`Page.captureScreenshot`, device px) with `scaleFactor: dpr` and `maxDimension: policy.annotateMaxDimension` (default 1800, `screenshot-policy.ts:31`). Any capture with a long edge > 1800 px — i.e. virtually every screen wider than 1800 device px, including 1920×1080@1x — downscales, so the buggy path is the common case, not an edge case.
- [C] Test gap: `tests/screenshot-annotator.test.ts:255-268` asserts only canvas dimensions for `maxDimension`; the scaleFactor test (line 171) runs at `outScale = 1` where the transform is identity, so no test exercises coordinates at `outScale < 1`.

- [I] `dom/mutation-signal.ts:52,86-90` — `dirtyRootsByEpoch` grows one bucket per mutation batch (epoch bump) and buckets are deleted ONLY by `clearDirtyRoots` from `page-state.ts` walks (lines 553, 645, 824). On an idle-but-active page (background tab, paused loop, no extraction walk), the map accumulates one entry per mutation batch for the life of the content-script instance — bucket *content* is capped at `DIRTY_ROOTS_BUCKET_CAP` (128), but bucket *count* is unbounded.
- [I] `dom/utils/read-cache.ts:102-128` + `dom/utils/viewport-signature.ts:19-21` — cross-step staleness for CSS-animation geometry: the shared read cache invalidates only on DOM epoch or scroll/resize signature, and CSS `@keyframes`/WAAPI animations change rects/opacity without firing MutationRecords. `getBoundingClientRect`/`getComputedStyle` values (and visibility derived from them) are served stale across steps to the RAW extraction walk (`page-state.ts:585,622`), which the loop consumes for element coordinates. `viewport-tracker.ts`'s IntersectionObserver refreshes only viewport *membership*, not rects/style. `state-cache.ts` documents this tradeoff as deliberate for its own cached path, but the read-cache path feeds the live elements tree.

- [M] `llm/retry.ts:247-249` — stale docstring: "The HTTP transport does not pass it today; wire it from the calling layer". It IS wired: `transport-http.ts:148` passes `opts.providerId`, threaded from `route/client.ts:295` (`providerId: input.provider`) and every provider passes its id into `make()` (`openai.ts:97`, `azure.ts:166`, `openai-compatible.ts:184`, …). Code is correct; documentation has drifted.
