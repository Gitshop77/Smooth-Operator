# Internationalization

## Current state

The Cockpit UI is currently **English-only and not localized**. All user-facing
strings are hard-coded literals directly in the React components (view headers,
table column labels, button text, empty/loading states, error toasts, etc.).
There is no i18n framework, no locale routing, and no message catalog.

Examples of hard-coded strings:

- View titles/descriptions in `src/components/cowork/shared/view-header.tsx`
  and each `*-view.tsx` (e.g. "Security", "Live security event feed").
- Table column labels passed to `DataTable` (`["Severity", "Type", …]`).
- Button and status text ("Clear", "Refresh", "Blocked", "Allowed").

This works for a single-locale audience but cannot be adapted to other
languages without touching component source.

## Recommended direction

1. **Introduce a lightweight translation layer.** Either:
   - `next-intl` (recommended for Next.js App Router apps, supports locale
     routing and ICU message formatting), or
   - a minimal in-house `t()` helper backed by locale JSON files
     (`en.json`, `fr.json`, …) if a full framework is undesirable.
2. **Centralize strings.** Move literals into per-locale message catalogs and
   reference them via keys (e.g. `t("security.title")`) instead of literals.
3. **Migrate incrementally.** Start with high-traffic strings — the view
   headers, primary action buttons, and table column labels — then sweep the
   remaining empty/loading/error states. Components should not change behavior
   or layout; only the string source changes.
4. **Avoid concatenating fragments into sentences**; use ICU placeholders
   (`{count} tabs`) so word order can differ across languages.

This document is documentation only — no components have been refactored.
